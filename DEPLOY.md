# Deploying

Currently live at **https://loqol-tds.onrender.com** (Render Starter, Oregon, Docker
runtime, Postgres). The instance stays warm, so there is no cold-start delay.

One service. The React app is built into `app/static` at build time and served by
the same FastAPI process, so there is no CORS to configure and no second origin
to secure.

## Render (blueprint)

`render.yaml` declares the web service and a free Postgres instance.

1. Push the repo to GitHub.
2. Render dashboard → **New → Blueprint** → pick the repo. It reads `render.yaml`.
3. Set the secrets Render cannot generate, under the service's **Environment**:

   | Key | Needed for |
   |---|---|
   | `OPENAI_API_KEY` | the voice lane; without it voice turns itself off and the UI says so |
   | `DOCUSEAL_API_KEY` | signature requests; without it the PDF renders locally instead |
   | `DOCUSEAL_TEMPLATE_ID` | `5507359`, or run `scripts/create_docuseal_template.py` against your own account |

   `SECRET_KEY` is generated by the blueprint and `DATABASE_URL` is wired from
   the database automatically.

4. Deploy. `/api/health` is the health check and reports which integrations are
   configured plus the form's field coverage.

## Anywhere else

Any host that runs a Python web service works. The build is:

```bash
pip install -r requirements.txt
cd web && npm ci && npm run build      # outputs into ../app/static
```

and the start command is:

```bash
uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

## Production checklist

- `ENVIRONMENT=production` — turns on `Secure` cookies and enables the startup
  config check.
- `SECRET_KEY` must be set explicitly. Without it every restart invents a new one
  and logs every agent out; the app warns about this on boot.
- `DATABASE_URL` must not be SQLite. Render's disk is ephemeral, so a SQLite
  database silently disappears on redeploy. The app warns about this too.
- `*.db-wal` and `*.db-shm` are gitignored alongside `*.db`. In WAL mode the
  sidecar holds the rows, and `*.db` alone does not match it.
- The startup hook fails the boot if any TDS field binding is invalid, because a
  mistyped field name produces a form that looks filled and is not.
